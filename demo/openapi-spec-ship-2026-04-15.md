## How to Regenerate Locally

```bash
npm run openapi
# Then open the output:
open public/openapi.json
```

Regeneration is idempotent. Re-running produces byte-identical output for the same source files.

## How to View the Spec

- **Local**: `http://localhost:3000/openapi.json` or `http://localhost:3000/api/openapi`
- **Hosted**: `https://<dealerSlug>.wolfpackauto.com/openapi.json`
- **Paste into Swagger UI**: https://editor.swagger.io/ — paste the JSON from either URL above

## Build Hook

`npm run build` now runs `npm run openapi` first. Every Vercel deploy regenerates the spec —
no manual step, no drift.

## Drift Protection

`src/__tests__/openapi-coverage.test.ts` asserts:
1. Every `route.ts` has a corresponding path in `public/openapi.json`.
2. Every exported HTTP method is documented on that path.
3. No phantom paths exist in the spec without a backing route file.

If a developer adds a route and forgets to run `npm run openapi`, the CI test suite fails
with a clear error listing the missing paths. Run `npm run openapi` to fix.

## Analytics

Every fetch of `/api/openapi` emits `system.openapi_fetched` with:
- `user_agent` — truncated to 200 chars
- `client_ip_hash` — SHA-256 of client IP, first 16 hex chars (privacy-safe cardinality metric)

This lets us see which clients are consuming the spec and how often.
