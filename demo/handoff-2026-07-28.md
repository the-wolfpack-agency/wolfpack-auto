## Email (wolfpack-auto): working, for the record

- Microsoft Graph app-only Mail.Send IS configured in wolfpack-auto prod
  (`MICROSOFT_CLIENT_ID/SECRET/TENANT_ID` + `MS_MAIL_FROM`, reusing the beyond-sku
  Azure app). A real invite email was received on live, so the transport works.
- Every email path (invite, rescind-then-reinvite, forgot-password, lead alerts,
  confirmations) routes through `dispatchEmail` -> Graph, with Resend only as a
  fallback if a key is present.
- Gotcha for the future: `vercel env pull` REDACTS "Sensitive" vars to the
  literal string `[SENSITIVE]`. Do NOT mirror M365 creds between projects with a
  pull-then-add script; it copies the placeholder, not the secret. Set the real
  values from Azure. There is a helper at `~/Desktop/fix-invite-email.command`
  that verifies against Microsoft before writing.

## wolfpack-lms specifics

- **Shadow-mode persistence is per-process.** On the live demo (no
  `DATABASE_URL`) an imported course lives in the in-memory store and can reset
  on a serverless cold start. Fully durable import needs `DATABASE_URL` set
  (prod mode); the code already supports it.
- `next build` is decoupled from stylistic lint (`eslint.ignoreDuringBuilds`),
  because the repo has pre-existing `react/no-unescaped-entities` findings.
  Typecheck still gates the build; lint runs as its own non-blocking stage in
  `verify.sh` and CI.
